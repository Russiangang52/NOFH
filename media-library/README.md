# Собственная медиатека НОФХ

Эта папка — автономная копия 24 настоящих фотографий. Ничего не загружается со старого nofh.ru, Pexels или прокси при сборке и просмотре сайта.

## Что здесь

- `manifest.json` — имена, размеры, подписи, авторы и SHA-256 каждого оригинала.
- `originals/news/*.json` — 18 оригинальных JPEG/PNG из публикаций федерации, сохранённых в Base64.
- `originals/stock/*.json` — 6 ранее скачанных настоящих фотографий, также в Base64.

Base64 — не ссылка и не генерация картинки. Это все байты исходного файла в текстовом виде, чтобы фотография не потерялась при экспорте проекта, который пропускает бинарные файлы. После декодирования контрольная сумма совпадает с оригиналом.

## Сборка и перенос

Переносите папку `media-library` целиком вместе с `scripts/restore-photos.mjs` и `next.config.ts`.

`next.config.ts` перед сборкой запускает локальное восстановление. Скрипт проверяет SHA-256 и создаёт:

- `public/photos/news/` — JPEG/PNG для публикаций;
- `public/photos/stock/` — JPEG для общих блоков;
- `public/photos/nofh-originals.zip` — скачиваемый архив всех 24 снимков.

Ручное восстановление: `node scripts/restore-photos.mjs`.
Проверка без изменения файлов: `node scripts/restore-photos.mjs --check`.

Если даже один исходник отсутствует или повреждён, сборка завершится с понятной ошибкой, а не подставит чужую фотографию к публикации.

## Новые фотографии через админку

Откройте `/admin/photos` или «Новости → Фотография». Загрузите JPEG, PNG или WebP до 4 МБ. Сервер проверит содержимое, уменьшит слишком большое изображение и сохранит его в таблицу `media` вашей PostgreSQL-базы. Фотография получает собственный URL `/api/media/<id>` на вашем домене. Её можно использовать повторно из медиатеки.

Загрузки не пишутся в `public` на работающем Vercel: его файловая система доступна только для чтения. Поэтому новые изображения не исчезают при следующем деплое, пока используется та же постоянная база `DATABASE_URL`. Не удаляйте и не заменяйте эту базу без переноса данных.

В разделе «Фотографии» можно скачать исходный набор и отдельные загруженные изображения. Кнопка «Архив моих загрузок» собирает ZIP в браузере — поэтому архив не ограничен размером ответа serverless-функции. Это копия файлов; для переноса сайта на другую базу нужны также записи `news`, `media` и остальных таблиц. Настройте регулярные резервные копии PostgreSQL у своего провайдера.

## Vercel

1. Выберите корень проекта, где лежат `package.json`, `next.config.ts`, `src`, `scripts` и `media-library`.
2. Настройте `DATABASE_URL` на постоянную PostgreSQL-базу и `ADMIN_PASSWORD` на свой пароль. Рекомендуется отдельный случайный `ADMIN_SECRET`.
3. Примените существующую схему проекта к этой базе через Drizzle.
4. Выполните новый deployment. Обычная команда `npm run build` автоматически восстановит фотографии, дополнительная команда загрузки не нужна.
5. Проверьте `/photos/news/nngu-vyxodit-v-plej-off.jpg` и `/admin/photos` на своём домене.

`.env` с настоящими паролями не должен попадать в публичный репозиторий. Секреты Vercel указываются в Environment Variables.

Авторы снимков перечислены в manifest.json. Локальное хранение не отменяет авторских прав.
