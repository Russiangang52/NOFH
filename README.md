# НОФХ — сайт и панель управления

Next.js App Router + PostgreSQL + Drizzle. Публичные страницы и `/admin` используют одну постоянную базу.

## Фотографии независимы от старого сайта

**Отдельная папка `media-library` содержит все 24 оригинальные фотографии.** Это данные файлов, а не ссылки на nofh.ru или фотосток. Оригиналы закодированы в текст, чтобы не потеряться при скачивании проекта без бинарных файлов.

При `npm run build` конфиг автоматически запускает `scripts/restore-photos.mjs`. Скрипт без интернета проверяет контрольные суммы и восстанавливает JPEG/PNG в `public/photos`. Здесь же создаётся `nofh-originals.zip`, который можно скачать через раздел «Фотографии» в админке.

Полная инструкция: [media-library/README.md](media-library/README.md).

## Загрузки администратора

- `/admin/photos` — загрузка, выбор и скачивание фотографий, архив своих загрузок.
- `/admin/news/new` — создание публикации с новой фотографией или файлом из медиатеки.
- JPEG/PNG/WebP до 4 МБ; проверка содержимого, коррекция ориентации, ограничение размера и безопасное перекодирование в WebP.
- Загруженные файлы сохраняются в таблице `media` вашей PostgreSQL-базы. Адрес `/api/media/<id>` принадлежит вашему сайту.
- Перезапуск или новый деплой не удаляет их, если подключена та же постоянная база. Временная файловая система Vercel не используется.
- Серверы nofh.ru и Pexels не участвуют ни в загрузке, ни в выдаче изображений. При отсутствии фотографии нет подмены снимком другого события.

## Запуск

1. Установите зависимости: `npm install`.
2. Заполните `.env` по `.env.example`. Используйте собственные `DATABASE_URL`, `ADMIN_PASSWORD` и `ADMIN_SECRET`.
3. Примените схему: `npx drizzle-kit push --config drizzle.config.ts` (к базе, указанной в `DATABASE_URL`).
4. Для разработки: `npm run dev`. Для сборки: `npm run build`.

Первоначальные новости создаются только в пустой базе. Они не перезаписывают материалы, добавленные администратором.

## Развёртывание на Vercel

Перенесите **весь проект**, включая `media-library`, `scripts`, `src`, `public`, `next.config.ts`, `package.json` и lock-файл. `media-library/originals/*.json` обязательны: они позволяют восстановить фотографии, даже если исходная папка `public/photos` не попала в экспорт.

В настройках Vercel добавьте `DATABASE_URL` постоянной доступной PostgreSQL-базы и собственный `ADMIN_PASSWORD`. Рекомендуется отдельный случайный `ADMIN_SECRET`. Секретный `.env` не публикуйте в Git. Схема должна быть применена к базе перед запуском административных функций.

Стандартной команды `npm run build` достаточно для восстановления фотографий. В логах сборки будет `[photos] 24 локальных оригинала проверены`.

Проверьте на своём домене:
- `/photos/news/nngu-vyxodit-v-plej-off.jpg` — оригинал без внешних запросов;
- `/photos/nofh-originals.zip` — архив исходных фото;
- `/admin/photos` — новые загрузки (после входа);
- `/api/health` — соединение с базой.

База данных — постоянное хранилище ваших публикаций и загруженных изображений. Настройте её резервные копии. ZIP из админки сохраняет файлы, но для полного переноса на другую базу нужно перенести и записи PostgreSQL.
